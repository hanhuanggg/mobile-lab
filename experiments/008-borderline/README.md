# 边境防线 / BORDERLINE

原创未来工业战术塔防 MVP。TypeScript、Phaser 3、Vite；HTML/CSS 指挥界面与 Canvas 2D 战场，无后端。

## 运行

在 **仓库根目录** 或本目录执行：

```sh
npm install
npm run dev
```

打开 `http://localhost:5173/`。手机与电脑在同一网络时，也可访问 Vite 输出的 Network URL；作战优先横屏，竖屏自动暂停并提示旋转。

```sh
npm run build
```

构建先执行 TypeScript 检查，随后将完整静态网页输出到本目录的 `dist/`，并同步 `index.html`、`assets/`、字体和原创 SVG 到本目录。同步结果纳入版本控制，适配本仓库 **main 分支根目录的 GitHub Pages** 配置，无需新增 Actions 或后端。

独立地址：`/mobile-lab/experiments/008-borderline/`。所有发布资源采用相对路径。也可仅部署本目录 `dist/` 到任意静态主机。仓库首页和旧作品继续使用现有静态服务器。

## 操作

- 首页点「开始作战」。选择底部干员 → 点击高亮格 → 选择四个方向之一 → 确认部署。
- 黄色高亮代表合法部署位置；重装、先锋、近卫站在地面，狙击、术师、医疗站在高台。
- 点场上干员查看生命、范围与充能；技能就绪后手动释放。先锋补给自动触发。
- 「撤退」返还初始费用的 50%（向下取整），并进入该类再部署冷却；阵亡不返费。同类同时最多 2 名，在场最多 8 名。
- `1–8` 选择干员，`Space` 暂停/继续，`F` 释放所选干员技能，`Esc` 取消选择。选方向时也可用方向键与 `Enter`。
- 暂停期间可以布防。倍速、重新开始、返回终端、音效设置均在界面中提供。手机可完成全部操作。
- 手机短横屏使用紧凑部署栏，将主要空间留给完整战场；顶部四角图标可进入全屏。浏览器工具栏伸缩和旋转会根据实际可见高度重新布局，无需刷新或重新开局。

## 第一关

12 × 7 工业平台，两条固定路线，3 点防线完整度，初始 10 DP，每秒 +1，费用上限 99。全关 37 名敌人，三阶段分别在 0、52、104 秒开始；最终破阵者在第 140 秒进入下路。普通突破扣 1 点，破阵者突破扣 3 点。最后一名敌人处理完毕、仍有生命时胜利。

前期先用「隼线」建立先锋经济，留意下路；中期加入法术火力。医疗的朝向需要覆盖前线；蓄势剑士平时不攻击、不阻挡，爆发必须手动开启。没有随机数值、成长、装备或永久强化。

## 源码

| 文件 | 职责 |
| --- | --- |
| `source/src/main.ts` | 页面流程、交互、部署方向、选择、暂停、结算、本地记录 |
| `source/src/game/config.ts` | 集中的 8 种单位参数、4 种敌人、地图、波次、方向范围 |
| `source/src/game/model.ts` | 引擎无关的确定性模拟：DP、路径插值、阻挡、伤害、治疗、技能、撤退与死亡 |
| `source/src/game/scene.ts` | Phaser 场景、2.5D 地图、触控命中、角色绘制、特效 |
| `source/src/game/art.ts` | 原创 SVG 角色与职业差异 |
| `source/src/game/audio.ts` | 可选的 Web Audio 原创合成音效 |
| `source/src/style.css` | 响应式工业战术 UI、横屏与减少动效支持 |
| `source/public/frontier.svg` | 原创首页指挥官与工业背景 |

逻辑使用最大 1/30 秒子步，支持 2 倍速下可靠的移动与阻挡判定。攻击以真实范围、阻挡、伤害和治疗计算决定，动画只反映已经发生的战斗事件。目标优先选择自身阻挡对象，其次选择路径进度最靠前者。第一版没有空中敌人。

`localStorage` 键为 `borderline-v1`，保存音效开关、行动次数、通关次数、最佳完整度和通关时间。浏览器拒绝存储时仍可完整游戏。开发模式提供 `window.__borderline` 供复现测试，生产构建移除该入口。

战场采用 Phaser Canvas 2D 渲染器，避免移动端旋转和图形上下文恢复时的 WebGL 视口差异。每帧绘制前按实际 Canvas 缓冲区同步相机，触摸坐标直接从 Canvas 的屏幕矩形换算；ResizeObserver 和 visualViewport 同步战场容器、浏览器工具栏及全屏变化。

## 测试

```sh
npm test
npx playwright install chromium  # 没有系统 Chromium 时首次执行
npm run test:e2e
```

浏览器测试优先使用 `CHROMIUM_PATH` 环境变量，其次 `/usr/bin/chromium`，否则使用 Playwright 自带 Chromium。端到端测试启动或复用 Vite，不依赖生产环境调试入口。详细验证结果见 [VERIFICATION.md](VERIFICATION.md)。
